## Description Help

На шаге `Description` пользователь описывает продукт простыми словами, а агент переводит это в понятное описание продукта и его начальную архитектурную картину.

### Что полезнее всего заполнить в анкете

- какую проблему решает продукт и зачем он нужен;
- кто будет им пользоваться;
- 2–4 ключевых сценария использования;
- какой это тип приложения;
- какие крупные части системы уже видны;
- ограничения, допущения и out of scope.

### Почему мы рекомендуем кластерно-модульную архитектуру

В CodeAI Hub мы рекомендуем смотреть на продукт как на набор понятных частей, а не как на один большой и неясный блок.

Короткая идея такая:
- у продукта могут быть самостоятельные крупные части;
- внутри таких частей могут быть более мелкие рабочие блоки;
- между ними есть границы и понятные связи;
- чем яснее это описано в самом начале, тем легче AI помогает дальше без хаоса и без лишних догадок.

Это не значит, что пользователь обязан знать архитектурные термины заранее.
Достаточно описать продукт обычными словами. Агент сам должен постепенно перевести это в более строгую картину.

### Короткий словарь

- `Shell` — то, через что пользователь запускает или открывает продукт.
- `Самостоятельная часть продукта` — часть системы, которая живёт отдельно.
- `Cluster` — крупный блок из нескольких связанных модулей.
- `Module` — отдельный рабочий блок с одной понятной ролью.
- `Boundary` — граница между частями системы.

### Что происходит до submit

Когда анкета готова, пользователь нажимает `Submit questionnaire`.
После этого агент создаёт `Final_Description.md` и задаёт только недостающие вопросы.

### Что происходит после submit

После submit диалог продолжается, пока документ не станет достаточно сильной основой для следующего шага.
Агент должен останавливать вопросы, когда хватает информации для качественного baseline, но решение о переходе остаётся за пользователем.

### Итог шага

Итоговый артефакт:

` .codeai-hub/<workspace>/description/Final_Description.md `

Этот документ должен быть одновременно:
- понятен пользователю;
- полезен как база для следующего шага;
- достаточно структурирован, чтобы потом из него можно было выводить диаграммы и границы системы.
