# SolidWorks-WorkFlow — каноническая документация (SSOT)

Цель: заменить разросшуюся, плохо навигируемую документацию на **минимальный набор** SSOT‑документов, достаточный для:
- восстановления контекста в начале каждой сессии;
- внесения изменений “сразу в SSOT” при фикcах/фичах;
- однозначного выбора ссылки “куда смотреть и что править”.

## Структура

- `System/` — описание системы целиком (глобальные инварианты, карта компонентов, SSOT). **1 документ**.
- `Clusters/` — подсистемы/кластеры (Core Orchestrator, Project Manager и т.д.). По 1 документу на кластер.
- `Modules/` — простые модули (например provider‑модули: Claude/Codex/Gemini). По 1 документу на модуль.
- `Contracts/` — точечные контракт‑документы по конкретным механизмам (routing, continuity, critical UX/flows). Только то, на что реально ссылаются `System/` и `Clusters/`.
- `Archive/` — временное хранилище для миграции/истории. Не SSOT.

## Правила (чтобы не разъезжалось снова)

1) Любой фикс/фича обязаны обновлять SSOT:
- если изменение системное → `System/`;
- если изменение в подсистеме → соответствующий файл в `Clusters/`;
- если изменение провайдера → соответствующий файл в `Modules/`;
- если нужен отдельный контракт → добавить/обновить файл в `Contracts/` и сослаться на него из `System/`/`Clusters/`.

2) В `Contracts/` не должно быть “параллельного описания системы”. Только контракт по механизму + ссылки на владельцев.

3) Удаление старых документов делаем постепенно:
- сначала переносим каноническое содержимое сюда;
- затем правим обратные ссылки;
- затем удаляем старые файлы (последним шагом), когда `npm run check:links` зелёный.
