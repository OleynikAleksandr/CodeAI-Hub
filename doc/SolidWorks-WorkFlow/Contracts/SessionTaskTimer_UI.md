# Session UI — Task Execution Timer (HH:MM:SS) — Behavior Contract

**Scope:** Session UI (webview) — счётчик времени выполнения задач агентом.

**Applies to:**
- Session UI: `src/client/ui/src/session/`
- Styles: `media/session-view.css`

**Goal:**
- Во время выполнения задачи агентом показать “живой” индикатор прогресса (анимированный таймер).
- После завершения turn показывать накопленное время выполнения задач данным workflow‑агентом.
- Накопление не сбрасывается при continuity/rollover (смена `sessionId`).
- Накопление не теряется при перезагрузке ядра.

---

## 1) Что считаем временем (вариант A)

Мы считаем **время ожидания**: от момента, когда UI переходит в режим ожидания (пользователь/ядро отправили задачу и агент занят), до момента, когда агент закончил turn и UI снова готов принять ввод.

Практическая формулировка в терминах UI:
- **Start**: когда сессия переходит в состояние “агент занят” (input UX показывает ожидание).
- **Stop**: когда сессия вернулась в состояние “агент свободен” (input UX позволяет отправлять).

В счётчик включается и “resuming/continuity” ожидание, если оно блокирует нормальную работу пользователя (это тоже ожидание выполнения задачи).

---

## 2) Где отображаем таймер (placement)

### 2.1 Во время работы агента
- Таймер показывается рядом с wait/lock UX (внутри области ввода), чтобы было видно, что процесс идёт.
- Цифры обновляются раз в секунду.

### 2.2 После завершения turn
- Итоговая цифра (накопленный total) показывается под полем ввода справа, напротив подсказки:
  - `Press Enter to send, Shift+Enter for a new line`
- При следующем turn таймер продолжает “накручиваться” (total растёт).

**Важно:** если подсказка `Press Enter...` скрывается во время ожидания (lock), total всё равно остаётся видимым (таймер не исчезает).

---

## 3) Накопление (per workflow-agent)

Таймер накапливается не “по sessionId”, а по workflow‑агенту.

**Key (concept):**
- `workspacePath`
- `runSlug`
- `stage`
- `sessionKind`
- (опционально) `initiativeSlug` и provider id

**Инвариант:** при continuity/rollover новый `sessionId` должен продолжать тот же total.

---

## 4) Persist

Накопление хранится в `localStorage` webview.

Требования:
- total не пропадает при перезагрузке ядра.
- формат хранения устойчив к отсутствию `localStorage` (SSR/tests).

---

## 5) Формат и анимация

- Формат отображения: `HH:MM:SS`.
- Миллисекунды не считаем и не отображаем.
- Анимация смены цифр — 3D flip (визуально как `react-3d-flip-numbers`).

---

## 6) Edge cases

- `terminal_no_resume`: таймер не должен “накручиваться” в read-only сессии, но может отображать накопленный total.
- `force unlock`: даже если пользователь принудительно разблокировал ввод для набора текста, при активной работе агента таймер всё равно может продолжать считаться (индикатор “агент занят”).
- `prefers-reduced-motion`: анимации должны быть отключаемыми на уровне CSS.
