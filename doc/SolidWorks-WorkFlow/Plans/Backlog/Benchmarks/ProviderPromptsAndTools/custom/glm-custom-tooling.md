# Кастомные инструменты GLM — черновик

Статус: черновик для обсуждения
Обновлено: 2026-06-22

Исходный базовый снимок: `../native/codex-native-tooling.md`
Целевой провайдер: GLM 5.2 / сессии агента разработки GLM в CodeAI Hub

## Цель

Дать GLM практичную поверхность инструментов внутри CodeAI Hub без требования полной совместимости с нативной средой выполнения Codex. Минимально жизнеспособному GLM-агенту нужны запуск shell-команд, редактирование через patch, план/статус, просмотр файлов и изображений, а также опциональный поиск доступных инструментов и внешней информации.

## Минимальный обязательный набор

1. `exec_command`
2. `write_stdin`
3. `apply_patch`
4. `update_plan`

Это самый маленький набор, который позволяет GLM смотреть файлы и окружение, редактировать, запускать проверки и держать видимое состояние задачи.

## Рекомендуемый default-набор

Добавить:
- `request_user_input`
- `view_image`
- `browser`
- `tool_search`

Так GLM становится пригодным для UI-работы, проверки скриншотов и отложенного поиска plugin/tool-возможностей.

## Опциональный набор

Добавлять только если это разрешено политиками и поддержано продуктовой поверхностью:
- `web_search`
- `image_generation`
- `write_workflow_artifact` для managed workflow turn'ов с артефактами

## Отличие от нативных инструментов Codex

Нативный захват Codex содержит 20 инструментов и namespaces, включая MCP namespaces и goal-инструменты. Для первой рабочей версии GLM не нужен точный namespace-паритет. Кастомный профиль GLM должен начать с обязательного/рекомендуемого набора выше, а MCP namespaces стоит добавлять только после того, как путь провайдера GLM сможет надежно маршрутизировать namespaced tool calls.

## Вопросы для обсуждения

1. Давать ли GLM сразу полный Codex-like набор из 20 инструментов или начать с минимального набора.
2. Нужны ли GLM goal-инструменты на первом этапе.
3. Должен ли `write_workflow_artifact` быть доступен только managed workflow-агентам или также отдельным чатам.
