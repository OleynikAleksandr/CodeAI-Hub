# Planning: Questionnaire Auto-Scroll

## Контекст наблюдения
Источник — прогон тестового проекта `test-01` (Polyglot Dashboard) в приложении CodeAI Hub. При заполнении анкеты описания проекта пользователь вынужден вручную прокручивать форму вниз до кнопки «Отправить анкету». Это трение в UX самого приложения, а не задача тестового проекта.

## Цель доработки CodeAI Hub
Автопрокрутка формы анкеты описания:
- при открытии анкеты — к первому сверху незаполненному обязательному разделу (resume «с места, где остановился»);
- когда все обязательные разделы заполнены — к footer с кнопкой «Отправить анкету».

## Критерий обязательности разделов
Обязательные — все разделы, кроме помеченных «(optional)» / «(if any)»:
- Опциональные: §0 `pre_read_documents`, §8 `modules_draft`, §9 `boundaries_draft`, §10 `constraints`, §12 `notes`.
- Обязательные: §1 `meta.title`, §2 `project.stack`, §3 `short_description`, §4 `problem_and_goals`, §5 `users`, §6 `user_scenarios`, §7 `key_functions`, §11 `out_of_scope`.
- Последний обязательный раздел — §11 `out_of_scope`. §12 `notes` опционально.

## Границы изменения
- `description-questionnaire-panel.tsx` — вычисляет первый незаполненный обязательный раздел и признак полноты, передаёт их во view как опциональные пропы.
- `idea-questionnaire-view.tsx` (shared для idea- и description-анкет) — опциональный механизм автопрокрутки через refs + `scrollIntoView`. Без новых пропов поведение idea-анкеты не меняется (принцип закрытых модулей).

## Поведение прокрутки
- Initial (загрузка): один раз скролл к первому незаполненному обязательному разделу либо к footer, если всё заполнено.
- Completion: при переходе анкеты в полностью заполненное состояние — скролл к footer.
- При печати промежуточных разделов автопрокрутка не срабатывает (не дёргает пользователя).

## Не входит в scope
- Блокировка кнопки «Отправить» при неполной анкете.
- Валидация содержимого полей.
- Изменения `question-block.tsx` (закрытый модуль).
