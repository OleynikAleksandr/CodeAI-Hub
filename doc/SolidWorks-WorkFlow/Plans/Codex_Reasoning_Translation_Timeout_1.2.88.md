# Codex Reasoning Translation Timeout 1.2.88

**Status:** Approved for implementation
**Date:** 2026-04-27
**Owner:** Codex

## Problem

Release `1.2.87` correctly streams Codex reasoning summary paragraphs as separate thinking messages, but live retest showed that some paragraphs remain in English.

Observed evidence:

- source reasoning blocks are present in Codex app-server SDK log;
- the same blocks are present in native Codex rollout as `agent_reasoning`;
- CodeAI Hub dialog JSONL stores them as `assistant` messages with `tag: "thinking"`;
- Core sends them to the translation pipeline;
- translation returns `status: "fallback"` with `errorCode: "empty_translation"`;
- no `*.translations.jsonl` overlay is written for those message ids, so UI displays source English.

The failed examples completed near the current live reasoning translation timeout:

- `Running the Python script`: timeout `9288ms`, fallback after about `9481ms`;
- `Creating content outline`: timeout `8448ms`, fallback after about `8651ms`.

## Solution

Raise the minimum live session reasoning translation timeout from the current dynamic floor of `5000ms` to `15000ms`.

Keep the current per-character scaling and max cap:

- base timeout: `15000ms`;
- per-character addition: unchanged;
- max timeout: `30000ms`.

This keeps small reasoning paragraphs from timing out too aggressively while preserving the existing non-blocking fallback behavior and maximum bound.
