# Архитектура: варианты описания инициативы и работа с RUNS

**Status:** Approved (implemented in v1.1.403)
**Last updated:** 2026-01-11
**Scope:** UI + Core, этап «Описание инициативы», run-метаданные, анкета.

---

## 1) Проблема

1. Каждый старт этапа Description создаёт новый run, и пользователь не может вернуться к ранее созданному run.
2. Новые run получают пустую анкету, хотя ранее есть заполненные варианты.
3. Для выбора «лучшей версии описания» нужен список run‑ов и понятный механизм уточнения.

---

## 2) Цели

- Пользователь может выбрать **любой существующий run** и продолжить работу в нём.
- Новые run получают **последнюю заполненную анкету**, а не пустой шаблон.
- UI терминология описывает действие: «Описать инициативу → новый вариант / уточнить существующие описания».

---

## 3) UX (ключевое)

**Кнопка:** `Описать инициативу`

После нажатия:
1) **Создать новый вариант описания**
2) **Уточнить существующие описания** → список run’ов (отображаем только `runSlug`, напр. `001-gpt-5-2`)

**Поведение при выборе run:**
- если в `run.json` уже есть `providerSessionId` → выполнить provider resume и открыть диалог;
- иначе → открыть анкету этого run; отправка анкеты создаёт сессию **в этом же run**.

Важно: при выборе существующего run UI **не предлагает выбрать провайдера** — он определяется из `run.json` (fallback: эвристика по `runSlug`).

---

## 4) Run метаданные (run.json)

Минимальный состав:
- `runId` (стабильный идентификатор; используется API `select-current`)
- `runSlug` (человекочитаемое имя, уникальное)
- `createdAt`
- `lastQuestionnaireAt` (момент последнего изменения анкеты)
- `displayName` (опционально; сейчас = runSlug)
- `providerId` (опционально; сохраняется при auto-run или при старте сессии)
- `providerSessionId` (опционально; пишется только после фактического создания provider-сессии и нужен для resume)

`createdAt` не переиспользуем как «последнюю корректировку». Для выбора “самой полной версии” используем `lastQuestionnaireAt`.

---

## 5) Источник анкеты для новых run

**Алгоритм:**
1. При создании нового run ищем run с максимальным `lastQuestionnaireAt`.
2. Если найден — копируем его `idea/questionnaire.md` в новый run.
3. Если не найден — используем шаблон.

Это обеспечивает, что каждый новый run стартует с **последней заполненной версии анкеты**.

---

## 6) Обновление `lastQuestionnaireAt`

- Любая запись в `idea/questionnaire.md` должна обновлять `lastQuestionnaireAt` соответствующего run.
- Обновление происходит на стороне Core (по пути файла при `workspace-file-write`).
- Для старых run без поля `lastQuestionnaireAt` оно заполняется при первой же записи анкеты.

---

## 7) Изменения API/контрактов

1. `session:create` принимает опциональный `runSlug`.
2. Если `runSlug` передан — Core **не создаёт auto-run**, а использует указанный run.
3. UI при выборе существующего run формирует `session:create` с `runSlug`.

---

## 8) Совместимость и миграция

- Существующие `run.json` остаются валидными; новое поле `lastQuestionnaireAt` добавляется лениво при первом сохранении анкеты.
- `displayName` остаётся опциональным; UI может показывать только `runSlug`.

---
