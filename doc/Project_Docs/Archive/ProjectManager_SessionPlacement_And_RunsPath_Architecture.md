# Архитектура: Project Manager — размещение UI-сессии + новый путь runs (без Initiatives)

**Date:** 2026-01-17
**Status:** Approved
**Target release:** 1.1.431 (planned)

---

## 1. Проблема

### 1.1. Неверное место открытия UI-сессии после отправки анкеты
Сейчас после нажатия «Отправить анкету» в **Project Manager** и выбора провайдера:
- сессия **создаётся**, но UI-сессия отображается в **vscode-webview** (панель VS Code), а не в окне Project Manager.

Для текущего рефакторинга это неверно: пользователь ожидает, что сессия Idea Collector продолжит работу **внутри Project Manager**.

Дополнительно: анкета Description — это **артефакт**. Чтобы пользователь видел одновременно:
- заполненную анкету (как артефакт),
- и активную UI-сессию агента (Idea Collector),

нужно:
- **UI-сессию** показывать в **левой части центральной зоны Project Manager**,
- **анкету** открывать в **правой части (панель артефактов)**.

### 1.2. Неверный путь для runs (устаревшая сущность Initiatives)
Логика формирования папок runs в `.codeai-hub/` осталась старой и создаёт, например:
- `.codeai-hub/initiatives/codeai-hub/runs/010-gpt-5-2/`

Но сущность **Initiatives** удалена, поэтому путь должен быть без неё:
- `.codeai-hub/codeai-hub/description/runs/010-gpt-5-2/`

---

## 2. Цели

1. Отображать UI-сессию Idea Collector **в Project Manager**.
2. Отображать анкету Description как **артефакт** в правой панели.
3. Исправить базовый путь для runs в `.codeai-hub/` в соответствии с новой доменной моделью (без `initiatives/`).

---

## 3. Нецели (на этот поток)

- Не меняем протоколы провайдеров и обработку `session:stream`.
- Не меняем сборочный pipeline релиза.
- **Не делаем миграцию** уже созданных папок runs (в разработке допустимо удалить старые каталоги вручную).

---

## 4. Принятые решения

1. **Двойное открытие сессии допустимо**: если сессия, созданная из Project Manager, также появляется в vscode-webview — это не считается проблемой.
2. **Миграция старых runs не нужна**: старые `.codeai-hub/initiatives/**/runs/**` можно удалить, новая логика должна создавать только новый путь.

---

## 5. Предлагаемое решение

### 5.1. UI (Project Manager): сессия слева, анкета справа

Требуемое поведение:
- После создания idea-сессии (Idea Collector) Project Manager должен показать активную сессию в **левой** панели.
- Анкета Description должна отображаться в **правой** панели (Artifacts), чтобы пользователь видел сессию и анкету одновременно.

### 5.2. Storage: новый base path для runs

Нужно заменить конструирование путей runs таким образом, чтобы вместо:
- `.codeai-hub/initiatives/<initiativeSlug>/runs/<runId>/`

использовалось:
- `.codeai-hub/<workspaceSlug>/description/runs/<runId>/`

Где:
- `<workspaceSlug>`: нормализованный идентификатор workspace/проекта (например `codeai-hub`),
- `description`: фиксированный namespace (замена удалённой сущности Initiatives),
- `<runId>`: как сейчас (например `010-gpt-5-2`).

---

## 6. Контракты и точки интеграции

### 6.1. UI (Project Manager)
- Источник истины текущего выбранного sessionId должен жить в состоянии Project Manager UI (store/state).
- Создание сессии (`session:create`) инициируется из Project Manager так же, как сейчас.

### 6.2. Core / storage
- Формирование путей runs должно быть централизовано (одна функция/пакет), чтобы избежать расхождений.
