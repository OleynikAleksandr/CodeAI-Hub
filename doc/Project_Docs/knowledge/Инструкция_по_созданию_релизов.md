# Инструкция по созданию релизов CodeAI Hub

Эта памятка описывает порядок действий при подготовке нового релиза расширения. Она дополняет документ `doc/Project_Docs/knowledge/Local_Artifacts_Workflow.md`, где разобраны детали локального кеша и офлайн-сценарии. Перед началом обязательно обнови оба файла до актуальной версии.

## 1. Локальная подготовка артефактов
1. Очисти при необходимости `~/.codeai-hub` (или конкретные каталоги провайдеров/ядра/launcher).
2. Запусти все build-скрипты:
   ```bash
   ./scripts/build-core.sh <версия-core>
   ./scripts/build-claude-module.sh <версия-claude>
   ./scripts/build-codex-module.sh <версия-codex>
   ./scripts/build-cef-launcher.sh --force       # при смене версии CEF/launcher
   ```
   Скрипты автоматически положат архивы в `~/.codeai-hub/**/downloads/` и `~/.codeai-hub/releases/`.
3. Если требуется обновить CEF runtime, скачай архив вручную и скопируй его в те же каталоги (`downloads/` + `releases/`), затем убедись, что SHA-1 совпадает с манифестом.

## 2. Обновление манифестов и пакетов
1. Проверь версии в `package.json` VSIX и пакетах (`packages/core`, `packages/Claude_Module`, `packages/Codex_Module`).
2. Убедись, что манифесты в `assets/core/manifest.json`, `assets/providers/claude/manifest.json`, `assets/providers/codex/manifest.json`, `assets/launcher/manifest.json` указывают на свежие архивы (имя файла, размер, SHA-1).
3. Для CEF манифеста достаточно актуальной версии/sha с CDN (локальный кеш всё равно используется).

## 3. Сборка релиза
1. Запусти `./scripts/build-release.sh` (без аргумента скрипт увеличит patch-версию автоматически; можно передать `--version` при необходимости).
2. После успешной сборки проверь, что `codeai-hub-<ver>.vsix` лежит в корне репозитория, а `doc/tmp/releases/` содержит tar.bz2 архивы.
3. Протестируй VSIX локально: установи его и убедись, что лог сообщает `Using cached …` (если всё сделано правильно, обращений к сети не будет).

## 4. Документация и TODO
1. Обнови README (блок текущего релиза) и CHANGELOG с новым номером версии и коротким перечислением изменений.
2. Обнови `doc/TODO/todo-plan_*.md`, архитектурные документы и knowledge-base (обязательно ссылку на `Local_Artifacts_Workflow.md`).
3. Добавь новые инструкции, если изменился пайплайн (например, новые скрипты или шаги проверки).

## 5. Публикация
1. Перенеси артефакты из `doc/tmp/releases/` в GitHub Release с соответствующим тегом (VSIX + core + launcher + модули).
2. Сделай коммит вида `feat: vX.Y.Z - описание` и запушь в `main`.
3. Создай/обнови релиз на GitHub, приложи артефакты и кратко опиши изменения (можно взять текст из CHANGELOG).

Следуя этой памятке вместе с `Local_Artifacts_Workflow.md`, можно воспроизводимо собирать релизы, не ломая локальные установки и не тратя время на повторные загрузки.
