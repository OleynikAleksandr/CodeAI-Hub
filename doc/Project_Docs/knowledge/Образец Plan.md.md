## 0.2 Правила делегирования задач саб-агентам (для ручной оркестрации)

Если пользователь запускает несколько агентов параллельно (например, в разных терминалах), нужно избегать двусмысленностей.

- **Роли:**
  - **Оркестратор (пользователь/система)** распределяет задачи и собирает отчёты.
  - **Саб-агент (исполнитель)** делает только назначенную задачу.
- **Важно:** метка вида `[Агент A]` в плане — это *логический поток/стрим*, а не «имя процесса». Чтобы не путаться, для реальных исполнителей используйте `Worker-1/Worker-2/Worker-3`.
- **Принцип входного пакета (не ‘запрет’, а ‘правильная подача’):** оркестратор **не пересылает весь Plan.md**.
  Вместо этого саб-агенту выдаётся *входной пакет* (выжимка), который содержит ровно то, что нужно для выполнения.
- **Состав входного пакета:**
  - `assignment`: Task ID + цель + критерии готовности
  - `scope`: список файлов/пакетов (≤3) и запрет выходить за scope
  - `must_read`: минимум контекста (пути) + 2–5 пунктов краткого контекста о соседних задачах (только если нужно)
  - `handoff`: как отчитаться (что сделано, как проверить, какие пункты плана пометить `DONE`)
- **Правило волн:** саб-агент выполняет только свой `assignment` и **не начинает** задачи следующей волны без нового входного пакета от оркестратора.
- **Правило статусов:** саб-агент обязан в отчёте указать, какие пункты плана нужно пометить `DONE` (дата, commit hash).
  - Если задача меняет *глобальные шаблоны* в `~/.codeai-hub/templates/` (не в git), в плане фиксируется `Commit: N/A (global)` + дата + краткое подтверждение проверки.


## 1. Правила выполнения

### 1.1 Структура плана

```
Plan
├── Волна 1 (параллельно)
│   ├── [Агент A] Stream
│   │   ├── Task
│   │   └── Task
│   └── [Агент B] Stream
│       └── Task
├── Волна 2 (после Волны 1)
│   └── [Агент A] Stream
│       └── Task
└── ...
```

### 1.2 Правила параллелизма

- **Волна** — группа задач, которые можно выполнять одновременно
- **[Агент X]** — логический поток работы, можно раздать разным агентам
- **"Ждёт:"** — явная зависимость от результатов предыдущей волны
- Задачи **внутри одной волны** не зависят друг от друга
- Следующая волна начинается **только после завершения предыдущей**

### 1.3.1 Формат записи задач (читабельность)

- Для быстрого сканирования статусы ставятся в начале строки: `[TODO]`, `[IN_PROGRESS]`, `[DONE]`, `[BLOCKED]`.
- Вместо длинных блоков и markdown-чекбоксов используйте компактный формат: `Task` + `(scope: …; DoD: …; target commit: …)`.

### 1.3 Правила задач

- Каждая задача затрагивает **≤ 3 файлов**
- Если задача требует > 3 файлов — **разбить на подзадачи**
- После каждой задачи — **обязательный Git Commit**
- Коммит нельзя пропускать или объединять

### 1.4 Гейты качества

- В CodeAI Hub гейты обычно выполняются автоматически git-hook'ом при `git commit`.
- Исполнитель не тратит контекст на список команд; достаточно помнить: **красный hook = задача не закрыта**.
- Ручной прогон при диагностике: `./scripts/check-architecture.sh`.
