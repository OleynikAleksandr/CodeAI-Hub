# Quality Gate Watcher — Дизайн-документ

**Статус:** Черновик
**Компонент:** `scripts/quality-watcher.js`
**Роль:** "Хук", запускающий Агента Качества.

---

## 1. Постановка проблемы
Git пассивен. Он не генерирует события при изменении файла в рабочей директории (только при коммите/чекауте).
**Требование:** Нам нужно запускать Агента Качества *мгновенно*, когда файл появляется в `git diff` (т.е. сохранен/изменен), не дожидаясь коммита.

## 2. Решение: Polling Daemon (Наблюдатель)

Так как мы не можем полагаться на системные вотчеры файлов (сложно кросс-платформенно) или Git хуки (слишком поздно), мы реализуем **Опрашивающий Демон (Polling Daemon)**.

### 2.1. Жизненный цикл (Start/Stop)

**Запуск ("Триггер"):**
Поскольку Git не может авто-запускать процессы при редактировании файла, **Writer Agent** (или Разработчик) отвечает за то, чтобы Watcher был запущен.
*   **Механизм**: В системный промпт Writer Agent-а добавляется директива: *"Перед началом задач по кодингу, запусти `npm run quality:start` в фоне."*
*   **Идемпотентность**: Скрипт проверяет, запущен ли уже другой экземпляр (через PID файл или лок порта) и выходит, если да.

**Остановка ("Авто-очистка"):**
*   **Тайм-аут**: Если `git diff` остается пустым в течение **15 минут** (настраиваемо), Watcher завершает свою работу.
*   **Логика**: "Активной работы не обнаружено. Экономим ресурсы. Пока."

### 2.2. Основной цикл (The "Hook")

Скрипт запускает бесконечный цикл (например, каждые 2 секунды):

1.  **Проверка состояния Git**:
    ```bash
    git diff --name-only HEAD
    ```
2.  **Фильтрация**:
    *   Игнорировать файлы, которые уже в обработке (`processing_queue`).
    *   Игнорировать файлы в `.gitignore`.
    *   Игнорировать не-исходные файлы (настраиваемо).
3.  **Триггер**:
    *   Если обнаружен новый файл `src/A.ts` в diff:
        *   Добавить в `processing_queue`.
        *   **Запустить Quality Agent**:
            ```bash
            codex exec --cwd .codeai/quality-agent "Fix ../../src/A.ts ..."
            ```
4.  **Мониторинг дочернего процесса**:
    *   Ждать завершения Quality Agent.
    *   **Exit 0 (Успех)**: Файл теперь должен быть чистым (закоммичен или откачен).
    *   **Exit 1 (Ошибка)**: Пометить файл как "Failed", чтобы избежать бесконечного цикла повторов (пока timestamp файла не изменится).
5.  **Освобождение**: Удалить из `processing_queue`.

## 3. Детали реализации

*   **Язык**: Node.js (Родной для проекта).
*   **Зависимости**: `simple-git` (опционально, или просто `child_process`), `chokidar` (опционально, но опрос `git diff` надежнее для "Git-centric" логики).
*   **Управление состоянием**: In-memory Set из `processing_files`.

## 4. Почему это соответствует "Git-centric"
*   Источник правды — **Git Diff**, а не файловая система.
*   Если файл игнорируется Git, Watcher его тоже игнорирует.
*   Если файл в индексе (`git add`), он все равно в `diff HEAD` (если не проверять `diff --staged` тоже). *Уточнение: Мы должны проверять и то, и другое, или просто `diff HEAD`, который покрывает разницу между рабочей копией/индексом и HEAD.*

---

## 5. Пример рабочего процесса

1.  **Writer Agent** начинает работу. Запускает `npm run quality:start`.
2.  Watcher стартует, создает `.codeai/watcher.pid`.
3.  Writer Agent редактирует `src/Login.ts`. Сохраняет.
4.  Watcher loop -> `git diff` показывает `src/Login.ts`.
5.  Watcher запускает **Quality Agent** (Codex).
6.  Quality Agent исправляет и коммитит `src/Login.ts`.
7.  Watcher loop -> `git diff` пуст.
8.  ... 15 минут спустя ...
9.  Watcher завершается.
