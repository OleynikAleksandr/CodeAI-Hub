# Unified Session Stream Audit (2025-11-03)

This note captures the current behaviour of the provider wrappers that feed the remote bridge so we can attach the unified JSONL writer in the next steps.

## Claude (`packages/Claude_Module`)
- **Session lifecycle:** temporary IDs come from `SDKSessionLifecycle.generateTemporaryId()`. The real `session_id` is discovered by tailing the SDK JSONL file (`messaging/message-processor.ts`, lines 176-212) and promoted via `session.eventEmitter.emit("realSessionId", …)`.
- **Events surfaced to core:**
  - `user_input` with `content`, synthetic `uuid`, timestamp (emitted before SDK call).
  - `assistant` with merged text blocks, `uuid`, and metadata (model, session id).
  - `dialog_message` with role `thinking` for Claude "thinking" blocks (`emitThinkingChunks`).
  - `error` envelopes on stream failures.
- **Dispatch pipeline:** `SDKMessageProcessor.processResponses()` pushes everything through the `SDKSessionManager` event emitter; `ClaudeProviderAdapter` subscribes and replays to the core bridge (see `provider/claude-provider-adapter.ts`, lines 62-107).
- **Writer hook candidates:** attach once `session.eventEmitter` announces `realSessionId` and reuse the existing `message` listener to mirror every payload.

## Codex (`packages/Codex_Module`)
- **Session lifecycle:** temporary IDs come from `CodexSessionLifecycle.generateTemporaryId()`. The first `thread.started` event carries the stable thread id; `CodexMessageProcessor.handleThreadStarted()` updates the registry and emits `sessionIdChanged` (`messaging/message-processor.ts`, lines 167-189).
- **Events surfaced to core:**
  - `user_input` for user prompts (suppressed when `internalTurn` is true).
  - `turn_started` / `turn_completed` / `turn_failed` usage envelopes.
  - `stream_event` with incremental assistant chunks (`kind: "assistant_chunk"`).
  - `assistant` with final assistant text (`uuid` = thread item id).
  - `dialog_message` for `thinking` summaries (`role: "thinking"`).
  - `error` emissions for processor, turn, and stream failures.
- **Dispatch pipeline:** `CodexProviderAdapter` relays `message`, `error`, and `sessionIdChanged` events to the remote bridge (see `provider/codex-provider-adapter.ts`, lines 60-118).
- **Writer hook candidates:** initialize once `sessionIdChanged` provides the canonical thread id; mirror both `message` payloads and the `stream_event` envelopes so JSONL captures incremental chunks.

## Gemini (`packages/Gemini_Module`)
- **Session lifecycle:** `GeminiSessionManager.createSession()` builds the session from CLI config. If `config.getSessionId()` already returns a value, the manager promotes immediately and emits `realSessionId` / `sessionIdChanged` on the event emitter (`session/gemini-session-manager.ts`, lines 146-195).
- **Events surfaced to core:**
  - `GeminiSessionManager.emitEvents()` currently forwards only `type: "assistant"` packets generated after a turn completes (`ALLOWED_EVENT_TYPES`).
  - `emitDialogMessage()` pushes `dialog_message` with roles `thinking` (thought summaries) or `assistant` for streaming text during the turn.
  - `error`, `system`, `warning` events are generated by `messaging/message-processor.ts` but are filtered out by the current allowed-type guard.
- **Dispatch pipeline:** `GeminiProviderAdapter` subscribes to `message`, `error`, `realSessionId`, and `sessionIdChanged` (see `provider/gemini-provider-adapter.ts`, lines 30-83).
- **Writer hook candidates:** create the writer as soon as `realSessionId` fires (the CLI can emit a stable ID up-front). We must extend the emission path so `GeminiSessionManager.emitEvents()` forwards non-assistant types; otherwise the writer will miss system/warning metadata.

## Remote bridge expectations (`packages/core/src/remote-bridge/index.ts`)
- Interprets provider payloads with `type` fields and appends them to the in-memory session (`appendProviderMessage`, `appendDialogMessage`).
- Binds `sessionIdChanged` and `realSessionId` events to keep track of provider session ids.
- Broadcasts everything downstream as `session:message` notifications to the webview (`SessionManager.appendMessage`).

## Next integration steps
1. Surface a unified message envelope (role, text, metadata) at the point where providers emit to the bridge.
2. Introduce a per-session writer that attaches after `realSessionId` and mirrors each event before it hits the bridge.
3. Ensure Gemini stops filtering non-`assistant` events so JSONL captures the same information the UI displays.

These notes underpin the design for the JSONL writer/reader work.

## Update — 2025-11-07
- The VS Code extension now passes the workspace path to the launcher, and the launcher writes it into `config/config.json`; `EnsureGlobalEnvironment` всегда использует это значение. Дополнительно расширение сохраняет slug в `~/.codeai-hub/state/workspace-path`, поэтому даже автономный запуск лаунчера без аргументов восстанавливает корректный путь. Нормализованные JSONL файлы снова попадают в `~/.codeai-hub/sessions/-<slug>/<provider>/`, даже если ядро перезапускает standalone UI.
- При одновременной работе двух UI история не теряется: `UnifiedSessionStorage` получает `providerSessionId` из тех же эвентов и создаёт writer сразу после промоушена.
