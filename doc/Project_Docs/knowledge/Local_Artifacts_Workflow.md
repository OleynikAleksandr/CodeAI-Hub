# Локальная работа с артефактами CodeAI Hub

Этот документ описывает, где хранятся локальные артефакты при разработке и как компоненты системы (установочные скрипты, Core Supervisor, расширение, лаунчер) ищут их перед обращением к удалённым источникам. Читай его перед каждой сессией, если планируешь работать с установкой провайдеров или обновлением рантайма.

## Структура каталогов

Все скрипты сборки складывают артефакты в домашний каталог разработчика, чтобы их можно было переиспользовать без загрузки на GitHub Releases:

- `~/.codeai-hub/cef/<platform>/<version>/` — распакованный CEF runtime
- `~/.codeai-hub/cef/<platform>/downloads/<archive>` — кешированный архив CEF (`*.tar.bz2`)
- `~/.codeai-hub/cef-launcher/<platform>/<version>/` — установленный `CodeAIHubLauncher`
- `~/.codeai-hub/core/<platform>/<version>/` — собранный бинарь core orchestrator
- `~/.codeai-hub/providers/claude/<version>/` — модуль Claude
- `~/.codeai-hub/providers/codex/<version>/` — модуль Codex
- `~/.codeai-hub/providers/*/downloads/<archive>` — кеши архивов провайдеров
- `~/.codeai-hub/releases/` — общий кеш для архивов, которые должны быть доступны всем установщикам

Скрипты уже автоматически заполняют эти каталоги:

- `./scripts/build-claude-module.sh --version <semver>` — устанавливает модуль Claude и кладёт архив в `downloads/`.
- `./scripts/build-codex-module.sh --version <semver>` — делает то же для Codex.
- `./scripts/build-core.sh --version <semver>` — собирает core и складывает архив в локальные кеши.
- `./scripts/build-cef-launcher.sh [--cef-version <версия>]` — пересобирает лаунчер, обновляет `doc/tmp/releases/CodeAIHubLauncher-*.tar.bz2` и кеши `~/.codeai-hub/releases/` + `~/.codeai-hub/cef-launcher/<platform>/downloads/`.

## Порядок поиска артефактов

Все установочные компоненты (скрипты `./scripts/build-*.sh`, будущий Core Supervisor, исторически — установщики внутри extension/launcher) должны использовать один и тот же порядок поиска артефактов:

1. **Готовая установка.** Если в целевой папке есть валидный `install.json` и ключевые файлы (`dist/index.js`, `codeai-hub-core`, `.app` и т.д.), используется существующая версия.
2. **Локальный архив `downloads/`.** Если в подпапке `downloads/` найден архив с подходящим SHA-1, он распаковывается заново.
3. **Глобальный кеш `~/.codeai-hub/releases/`.** Если артефакта нет в `downloads/`, ищем общий архив в `releases/`.
4. **Удалённый URL из манифеста.** Только если локальные варианты не подошли, происходит загрузка по ссылке из `assets/**/manifest.json`.

При ошибке загрузки теперь указывается компонент (например, «Claude module download failed…»). Проверь соответствующий манифест и удостоверься, что архив либо лежит локально, либо опубликован по указанному URL.

Важно: в целевой архитектуре автономного ядра (см. `doc/AutonomousCore_Architecture.md`) ответственность за установку и поиск артефактов постепенно переезжает из UI-клиентов (extension/launcher) в уровень Core Supervisor и install-скриптов. UI-клиенты должны только подключаться к уже установленному ядру и провайдерам, не выполняя скрытых установок во время старта.

## Автономное ядро и Core Supervisor (целевое состояние)

После перехода к архитектуре Autonomous Core общая модель работы с артефактами будет выглядеть так:

1. **One-shot install через скрипты и Supervisor.**
   - Локальные артефакты ядра и провайдеров по-прежнему собираются скриптами:
     - `./scripts/build-core.sh <version>`
     - `./scripts/build-claude-module.sh <version>`
     - `./scripts/build-codex-module.sh <version>`
     - при необходимости `./scripts/build-cef-launcher.sh`
   - Дополнительно поверх них появляется Core Supervisor (см. архитектурный документ), который:
     - читает `~/.codeai-hub/releases/` и `~/.codeai-hub/**/downloads/`;
     - проверяет наличие установленных компонентов в целевых каталогах (`~/.codeai-hub/core/**`, `~/.codeai-hub/providers/**`);
     - запускает ядро, используя уже подготовленные артефакты.

2. **UI-клиенты не выполняют установку на старте.**
   - VS Code extension и CEF launcher не должны запускать установку core/провайдеров в фоне при активации.
   - Вместо этого они:
     - вызывают Core Supervisor для запуска/проверки состояния ядра;
     - получают от ядра список активных/неактивных провайдеров;
     - при необходимости запускают явные сценарии `Repair installation` (через Supervisor/CLI), но не «лечат» систему автоматически.

3. **Core Orchestrator сам ищет и поднимает провайдеры.**
   - При старте ядро сканирует `~/.codeai-hub/providers/*/<version>/` и пытается подключить каждый модуль (см. Provider Registry в архитектурном документе).
   - Ошибки отдельных провайдеров отражаются в статусе ядра, но не останавливают его целиком.

## Чек-лист перед сборкой релиза

1. Запусти скрипты компонентов, чтобы обновить локальные установки:
   - `./scripts/build-core.sh <version>`
   - `./scripts/build-claude-module.sh <version>`
   - `./scripts/build-codex-module.sh <version>`
   - при необходимости `./scripts/build-cef-launcher.sh`
2. Убедись, что в `~/.codeai-hub/releases/` лежат актуальные архивы core/launcher/CEF/provider’а.
3. Запусти `./scripts/build-release.sh`, чтобы собрать VSIX.
4. После публикации скопируй архивы из `doc/tmp/releases/` в релиз на GitHub, чтобы пользователи получили те же файлы, что и в локальном кэше.
5. Для проектов с автономным ядром дополнительно проверь:
   - что автономное ядро поднимается без участия UI-клиентов (через Core Supervisor/CLI);
   - что VS Code extension и лаунчер успешно подключаются к уже работающему ядру и не инициируют установку артефактов;
   - что ядро корректно обнаруживает все установленные провайдеры и отражает их статус в API (`/status` / `/providers`).

## Решение проблем

- **Скачивание завершилось ошибкой.** Проверь, есть ли архив в `~/.codeai-hub/.../downloads/` или `~/.codeai-hub/releases/`. При необходимости удали `install.json`, чтобы форсировать повторную установку.
- **Ошибка SHA-1.** Пересобери компонент соответствующим скриптом, обнови SHA-1 в манифесте и снова запусти `build-release.sh`.
- **Несовпадение версии.** Убедись, что версия в манифесте совпадает с названием папки под `~/.codeai-hub/...`. Скрипты инкрементируют версию автоматически, манифест нужно обновлять перед упаковкой VSIX.

Следуя этому процессу, ты избежишь повторных загрузок и гарантируешь, что манифесты всегда указывают на действительно существующие артефакты. Работай по инструкции — и установка в режиме разработки всегда будет офлайн.
