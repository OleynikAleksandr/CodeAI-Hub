# FlowNode Continuity — Matrix Rain Input Lock Animation Architecture

**Date:** 2026-02-06
**Status:** Approved baseline for Phase 100 implementation
**Owner:** Oleksandr

---

## 1. Цель

Сделать состояние блокировки ввода визуально понятным и «живым», когда в диалоге временно нет новых сообщений:
- при `running` и `blocked` пользователь видит тонкую фоновую Matrix Rain-анимацию внутри поля ввода;
- смена continuity-сессии воспринимается естественно и без тревожного UX;
- copy в поле ввода согласован с новым правилом:
  - `Agent is resuming your session… Please wait.` (handoff / continuity block)
  - `Agent is working… Please wait.` (обычное выполнение)

Вдохновение: визуальный стиль `Rezmason/matrix` (WebGL reference), но реализация должна быть облегчённой и безопасной для текущего UI Project Manager.

---

## 2. UX-принципы

1. Анимация не должна быть доминирующей: фон очень тусклый, надпись читается без напряжения.
2. Состояние «занят/переключение» должно быть очевидным даже при тишине в чате.
3. Ввод блокируется строго синхронно с wait-copy (никакого расхождения «надпись ждите, а поле уже активно»).
4. Анимация работает только в период lock (`running`/`blocked`) и полностью выключается в `idle`.
5. Для `prefers-reduced-motion` анимация заменяется на статичный мягкий фон.

## 3. Визуальная спецификация Matrix Rain

### 3.1 Область рендера
- Только фон контейнера ввода (`session-input__container`), не весь экран.
- Canvas-слой расположен под текстом textarea и placeholder.
- `pointer-events: none`, чтобы не влиять на UX ввода/drag&drop.

### 3.2 Характер анимации
- Вертикальные «дожди» из символов идут сверху вниз.
- Скорость колонок разная и несинхронная.
- Колонки бесшовно перезапускаются после выхода за нижнюю границу.
- Визуальный шум мягкий: низкая альфа, короткий шлейф, без резких вспышек.

### 3.3 Плотность колонок (адаптивно к ширине)
- Количество колонок зависит от текущей ширины контейнера.
- Базовая формула: `columns = clamp(floor(width / columnWidth), minColumns, maxColumns)`.
- Рекомендуемые стартовые параметры:
  - `columnWidth`: 12-14 px
  - `minColumns`: 10
  - `maxColumns`: 140
- При ресайзе панели количество колонок пересчитывается автоматически через `ResizeObserver`.

### 3.4 Символы
- Набор символов: латиница верхний регистр + цифры (опционально технические символы `[]{}<>+-=`).
- Для читаемости и «old monitor» эффекта использовать моноширинный шрифт.

## 4. Цветовая модель

### 4.1 Цвет Matrix Rain (единый для всех провайдеров)
- Базовый цвет глифов: `#00ff41` (классический Matrix green).
- Начальная прозрачность глифов: `alpha: 0.30` (приглушение на 70%).
- Цвет глифов не зависит от активного провайдера.
- «Голова» потока может быть чуть ярче в пределах `alpha: 0.34-0.38`, без выхода в яркий неоновый контраст.

### 4.2 Цвет wait-copy (provider-aware)
Две надписи:
- `Agent is resuming your session… Please wait.`
- `Agent is working… Please wait.`

должны использовать цвет активного провайдера из табов:
- `claude`: `#ff9105`
- `codex`: `#01f0d8`
- `gemini`: `#ab34cb`
- fallback (если theme отсутствует): `#7f8c8d`

с приглушением на 30% (`alpha: 0.70`).

## 5. Технический подход (реализация)

### 5.1 Рендер-движок
- `Canvas 2D` в React-компоненте/хуке (`requestAnimationFrame`).
- Почему не WebGL:
  - локальный эффект на небольшую область (textarea container);
  - ниже сложность интеграции;
  - проще контролировать производительность и fallback.

### 5.2 Жизненный цикл
- Старт анимации: при переходе в `running` или `blocked`.
- Стоп анимации: при `idle`, unmount, смене активной сессии, скрытии компонента.
- Обязательная очистка RAF-loop и `ResizeObserver` (без утечек).

### 5.3 Модель колонок
Каждая колонка хранит:
- `x` (позиция),
- `y` (текущий сдвиг),
- `speed` (случайная в диапазоне),
- `length` (длина хвоста),
- `glyphSeed` (для детерминированного, но вариативного выбора символов).

Обновление кадра:
1. Полупрозрачное затемнение фона (создаёт хвост/затухание).
2. Отрисовка символов по колонкам с единым Matrix green (`#00ff41`, `alpha: 0.30`).
3. Смещение `y` по индивидуальной скорости.
4. Ресет колонок, вышедших ниже контейнера.

## 6. Синхронизация с lock-copy

Нужно ввести единый derived-флаг `inputLocked` (источник истины для UX):
- `inputLocked = connectionState !== "idle" || isQueued`
- `placeholder` и `fieldset disabled` используют один и тот же `inputLocked`/state branch.

Копирайтинг:
- при continuity handoff (`blocked`): `Agent is resuming your session… Please wait.`
- при обычном `running`: `Agent is working… Please wait.`
- при queued: `Message queued. Sending as soon as it is ready…`

## 7. Accessibility и безопасность

1. `@media (prefers-reduced-motion: reduce)`:
- отключить анимацию,
- оставить статичный слабый текстурный фон.

2. Контраст и читаемость:
- placeholder/ввод всегда читаются поверх анимации.
- при необходимости добавить overlay-mask между canvas и текстом.

3. Производительность:
- ограничить работу анимации только видимым активным input.
- throttling/fps cap (например, до 30-45 fps) при необходимости.

## 9. Критерии приёмки

1. При `running`/`blocked` поле ввода визуально показывает subtle Matrix Rain-фон.
2. При `idle` анимация полностью отсутствует.
3. Нет рассинхрона между текстом ожидания и disabled-состоянием.
4. При изменении ширины input area число колонок корректно адаптируется.
5. Нет видимых лагов, утечек RAF/observer и падений FPS в обычной работе.
6. В режиме reduced motion нет анимации, но есть аккуратный статичный фон.

## 10. Утверждённые решения (Phase 100)

1. Набор символов: только ASCII (латиница верхний регистр + цифры + базовые техсимволы).
2. Область активности: состояния `running` и `blocked`, в `idle` анимация выключена.
3. Settings-toggle для анимации в этой фазе не добавляется (можно вернуться в vNext).
