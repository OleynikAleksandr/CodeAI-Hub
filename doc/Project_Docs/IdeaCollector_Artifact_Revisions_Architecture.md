# Idea Collector — единый контракт и многократные финализации артефактов

**Дата:** 2026-01-12
**Статус:** Approved

---

## 1. Проблема
Текущий механизм ревизии артефактов усложнён:
- добавлен отдельный режим `revise_artifacts` и `artifact.patch`;
- в Claude message processor есть защита `structuredOutputFinalized`, которая блокирует повторный `finalize` в рамках одной сессии;
- итог: после первой финализации повторные корректировки не сохраняются, а схема и промпт усложняются.

Нужен **один простой контракт**, который:
- поддерживает многократные обновления артефактов;
- требует явного подтверждения пользователя («ОК/Утверждаю») перед записью;
- не вводит новые режимы, которые приходится объяснять промптом.

---

## 2. Цели
1. Один Structured Output контракт для всех этапов диалога.
2. Повторные обновления артефактов без смены режима (в рамках одной сессии).
3. Запись артефактов только после явного подтверждения пользователя.
4. Простая модель для агента: готов внести изменения → попроси «ОК/Утверждаю» → верни finalize.

---

## 3. Решение (контракт)
### 3.1 Единственный набор `next_action`
Оставляем **один** набор значений:
- `ask_question`
- `clarify`
- `summarize`
- `finalize`

### 3.2 Семантика `finalize`
`finalize` = «я готов записать артефакты **сейчас**». Это **не** означает «закрыть навсегда».
- Пользователь даёт явное «ОК/Утверждаю».
- Агент возвращает `finalize` с **полными markdown** артефактами.
- При новых правках агент снова просит «ОК/Утверждаю» и снова возвращает `finalize`.

### 3.3 Поля артефакта
Используются только полные markdown:
- `artifact.idea_markdown`
- `artifact.virtual_simulation_markdown`
- `artifact.idea_path`
- `artifact.virtual_simulation_path`

`artifact.patch` и `next_action=revise_artifacts` не используются.

---

## 4. Поведение компонентов
### 4.1 UI
- Сохраняет артефакты **каждый раз**, когда приходит `finalize`.
- Не блокирует повторные `finalize` внутри одной сессии.

### 4.2 Provider слой (Claude/Codex)
- Удалить логическую блокировку `structuredOutputFinalized`.
- Добавить защиту от дублей по `message.uuid` (если одно и то же сообщение приходит повторно).

### 4.3 Core
- Пишет артефакты на каждый `finalize` как overwrite.
- Использует текущие меры безопасности: backup + минимальная валидация заголовков.

---

## 5. Правила для промпта Idea Collector
- Когда агент готов внести изменения в артефакты, он **всегда** просит подтверждение: «ОК/Утверждаю?»
- Без подтверждения — агент продолжает обсуждение (ask_question/clarify/summarize).
- После подтверждения — агент возвращает `finalize` и полные markdown артефакты.
- После записи артефактов диалог может продолжаться (новый цикл правок).

---

## 6. Совместимость
- Важно сохранить обратную совместимость в логике парсинга: если придёт старый `revise_artifacts`, его можно трактовать как `finalize` или отклонять на стороне контракта (решить при реализации).

---

## 7. Риски
- Агент может забыть запросить подтверждение: решается строгими правилами промпта.
- Дублированные события `finalize` могут привести к двойной записи: решается дедупликацией по `uuid`.
