# Idea Collector — Универсальный контракт интервью и источник истины

**Date:** 2025-12-30
**Status:** Draft
**Owner:** Olekandr Oliinyk

---

## 1. Проблема
Idea Collector опирается на локальные шаблоны, которые не гарантированно попадают в prompt/structured output. Итог: секции пропускаются, Spec.md не готовится, а агент может пытаться читать внешние документы. Дополнительно есть перерасход токенов, когда агент публикует длинные документы прямо в диалоге.

## 2. Цель
Сделать контракт интервью **универсальным** (для любой идеи: продукт, фича, модуль) и обеспечить **единый источник истины**, который гарантированно получает агент при старте сессии. Минимизировать токены в диалоге за счёт запрета длинных документов.

## 3. Решение (высокоуровневое)
1. **Источник истины — Core**: ядро при старте читает templates (`~/.codeai-hub/templates/**`) и собирает канонический контракт Idea Collector.
2. **Контракт = prompt + schema + template**: единый объект конфигурации, отдаваемый UI через Core API.
3. **UI не читает файлы напрямую**: все данные приходят из контракта; локальный fallback допустим только при недоступности Core.
4. **Универсальность**: контракт не привязан к Flow/проекту и покрывает идеи от микро‑модуля до полноценного продукта.
5. **Адаптивное интервью**: первые ответы формируют контекст и масштаб, далее вопросы подстраиваются под глубину идеи.
6. **Экономия токенов**: в диалоге только краткая выжимка и путь к файлу; полный Idea.md сохраняется в workspace.

## 4. Архитектурные компоненты
- **Idea Contract Service (core, Remote Bridge)**
  - Загружает шаблоны и schema из `~/.codeai-hub/templates/**`.
  - Нормализует schema, инжектит template.
  - Возвращает `IdeaContractPayload` по HTTP.
- **HTTP endpoint**
  - `GET /api/v1/orchestrator/idea-contract`
- **IdeaCollectorService (UI)**
  - Запрашивает контракт у Core и использует его как единственный источник.
  - Локальный fallback применяется только если Core недоступен.

## 5. Контракт данных
**IdeaContractPayload**:
- `prompt`: string
- `schema`: JSON object (structured output schema)
- `template`: string (raw idea template)
- `version`: string (hash/mtime)

## 6. Принципы универсального интервью
- Никакой привязки к конкретным Flow/проектам по умолчанию.
- Стартовые вопросы выявляют **контекст и масштаб** (тип идеи, аудитория, критичность, глубина UI/данных/архитектуры).
- Глубина вопросов **адаптивна**:
  - для микро‑модуля: минимум UI/данных/архитектуры;
  - для приложения: полный контур и интеграции.
- Обязательные секции заполняются только там, где это релевантно масштабу.

## 7. Ограничения
- Агент не опирается на внешние документы вне контракта.
- Только prompt/schema, переданные в turn, являются гарантированным источником истины.
- Длинные документы в диалоге запрещены: показывается лишь краткая выжимка и путь.

## 8. Риски
- Несинхронность templates и contract при ошибке загрузки.
- Рост размера prompt/schema при расширении универсального контракта.

## 9. Критерии готовности
- UI получает contract из Core и не читает локальные файлы напрямую.
- Агент стабильно покрывает универсальные секции в интервью.
- Любые изменения templates отражаются в contract (hash/mtime).
- В диалоге нет полного текста Idea.md, только краткая выжимка + путь.
