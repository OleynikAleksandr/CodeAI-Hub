# Idea Collector — Универсальный контракт интервью и источник истины

**Date:** 2025-12-30
**Status:** Draft
**Owner:** Olekandr Oliinyk

---

## 1. Проблема
Сборщик идей опирается на локальные файлы шаблонов, которые могут быть не прочитаны (fallback-схема), а также не гарантируют, что агент получит актуальный контракт. Итог: пропуск секций, неполные интервью и несогласованность с будущим Spec.md.

## 2. Цель
Сделать контракт интервью **универсальным** (подходит для любой идеи) и обеспечить **единый источник истины**, который гарантированно получает агент при старте сессии.

## 3. Решение (высокоуровневое)
1. **Источник истины — Core**: ядро при старте читает templates (`~/.codeai-hub/templates/**`) и собирает канонический контракт Idea Collector.
2. **Контракт = schema + prompt + template**: единый объект конфигурации, отданный UI через RemoteBridge. UI больше не читает файлы напрямую.
3. **Универсальность**: контракт не привязан к конкретному Flow/проекту, покрывает идеи от микро‑модуля до полноценного продукта.
4. **Адаптивное интервью**: первые ответы формируют контекст, далее агент уточняет вопросы, подстраивая глубину по масштабу идеи.

## 4. Архитектурные компоненты
- **IdeaContractRegistry (core)**
  - Загружает шаблоны и schema из `~/.codeai-hub/templates/**`.
  - Нормализует/строгает schema, инжектит template.
  - Возвращает `IdeaContractPayload` для клиентов.
- **IdeaContractFacade (core)**
  - Единая точка доступа для UI/RemoteBridge.
- **IdeaContractRequestHandler (core)**
  - HTTP endpoint: `GET /api/v1/orchestrator/idea-contract`.
- **IdeaCollectorService (UI)**
  - Запрашивает контракт у Core и использует его как единственный источник.
  - Локальный fallback допускается только при недоступности Core.

## 5. Контракт данных
**IdeaContractPayload**:
- `prompt`: string
- `schema`: JSON object (structured output schema)
- `template`: string (raw idea template)
- `version`: string (hash/mtime)

## 6. Принципы универсального интервью
- Без упоминаний конкретных флоу/проектов по умолчанию.
- Стартовые вопросы выявляют **контекст и масштаб** (тип продукта, аудитория, сложность).
- Глубина вопросов **адаптивна**:
  - для микро‑модуля: минимум UI/данных/архитектуры;
  - для приложения: полный контур и интеграции.
- Все обязательные секции должны заполняться по мере необходимости масштаба.

## 7. Ограничения
- Модель не читает файлы, если их содержимое не инжектировано в prompt/schema.
- Только schema/prompt, переданные в turn, являются гарантированным источником.

## 8. Риски
- Несинхронность templates и contract при ошибке загрузки.
- Усложнение prompts может увеличить длину и стоимость токенов.

## 9. Критерии готовности
- UI получает contract из Core и не читает локальные файлы напрямую.
- Агент стабильно покрывает универсальные секции в интервью.
- Любые изменения templates отражаются в contract (hash/mtime).
