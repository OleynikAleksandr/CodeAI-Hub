# Архитектура: Idea Collector — Анкетирование (Questionnaire UI) вместо интервью

**Date:** 2026-01-04
**Status:** Approved

---

## 1) Проблема

Текущий формат Idea Collector построен как «интервью» (последовательные вопросы/ответы в чате). На практике это даёт несколько проблем:

- **Неполнота**: агент может забыть уточнить важные детали, особенно при длинном диалоге.
- **Невоспроизводимость**: разные сессии дают разный набор вопросов и разное покрытие.
- **Слабый контроль качества входных данных**: пользователь не видит «полного чеклиста» и часто пропускает блоки.
- **Контекст/лимиты**: длинные ответы в чате конфликтуют с правилом «не публиковать длинные документы в диалоге».

## 2) Цель

Перевести сбор исходных данных на **анкетирование**:

- Пользователь заполняет **одну** анкету (длинную форму) в UI.
- По кнопке **«Отправить анкету»** анкета отправляется в Idea Collector как контекст (через workspace file attach), а агент:
  - критически проверяет заполнение и соответствие контракту;
  - задаёт точечные уточняющие вопросы;
  - после «ОК/утверждаю» финализирует и создаёт артефакты (как сейчас): `idea.md` + `virtual-simulation.md`.

MVP: поддерживаем только тип анкеты **«Кластер»** (полная анкета).

## 3) Источник истины: шаблоны и контракт

### 3.1 Где храним шаблон анкеты

Шаблон анкеты хранится в глобальных templates:

- `~/.codeai-hub/templates/full-development-flow/idea/questionnaire-template.md`

Пользователь может править шаблон вручную; изменения должны отражаться в UI при старте стадии.

### 3.2 Как связать «контракт агента» и «анкету UI»

- `schema` (Structured Outputs) остаётся контрактом результата (что должно быть покрыто/проверено на finalize).
- В `idea-contract` добавляется поле `questionnaire`, которое содержит:
  - `templateMarkdown` (шаблон анкеты, который UI использует для генерации файла в workspace);
  - при необходимости (позже) — структурированный список вопросов для UI (id/title/hint/schemaPath).

MVP допускает передачу только `templateMarkdown`.

## 4) Workspace артефакт анкеты

При старте стадии Idea UI создаёт/обновляет файл анкеты рядом с будущими артефактами:

- `.codeai-hub/full-development-flow/initiatives/<initiativeSlug>/idea/questionnaire.md`

Правила:

- UI **не отправляет** анкету частями; единственная отправка — только в конце.
- UI сохраняет прогресс в файл по мере заполнения (debounced), чтобы не терять введённое.
- В чат отправляется **короткое** сообщение + путь к файлу, чтобы Core применил auto-attach и дал агенту текст анкеты без публикации её целиком в диалоге.

## 5) UI: экран анкеты (VS Code webview, MVP)

### 5.1 Основной UX

- Клик `Idea` открывает новый UI-экран «Анкета» (не чат).
- Длинная вертикальная прокрутка на уровне всей страницы.
- Каждый вопрос имеет поле ответа, визуально/поведенчески близкое к `InputPanel`.
- В конце — одна кнопка: **«Отправить анкету»**.

### 5.2 Переиспользование `InputPanel`

Требование: переиспользовать поведение поля ввода, включая drag-and-drop ссылок/путей, которое уже работает в:

- `src/client/ui/src/session/input-panel.tsx`

Решение:

- Выделить общий слой для textarea + dnd/insert логики (hook/компонент), который используется:
  - в `InputPanel` (как раньше),
  - в полях анкеты.

### 5.3 Авто-grow + ручное увеличение высоты (без внутреннего скролла)

Требования:

- Внутри поля ввода **не должно** быть прокрутки.
- Высота поля должна автоматически расти по мере ввода, учитывая переносы строк при изменении ширины.
- Пользователь может вручную «растянуть» поле по вертикали (аналог треугольника в правом нижнем углу), чтобы задать большую минимальную высоту.

Модель:

- `effectiveHeight = max(contentHeight, userMinHeight)`
- `contentHeight` пересчитывается по `scrollHeight` на ввод и на изменения ширины (wrap).
- `userMinHeight` изменяется только при ручном drag.

## 6) Отправка анкеты агенту

По нажатию «Отправить анкету»:

1. UI сохраняет `questionnaire.md`.
2. UI отправляет в чат короткое сообщение (например):
   - «прочитай `.codeai-hub/.../idea/questionnaire.md` и проверь по контракту; если нужно — задай уточнения; затем дождись “ОК/утверждаю” для finalize».
3. Core auto-attach прикрепляет содержимое файла (в рамках лимитов).
4. Агент продолжает в чате (уточнения → “ОК/утверждаю” → finalize → артефакты).

Если размер анкеты превысит лимит auto-attach (60KB/файл), MVP-стратегия: UI делит анкету на 2 файла `questionnaire.part1.md`/`questionnaire.part2.md` и отправляет оба пути.

## 7) Нефункциональные требования

- Не публиковать полный текст анкеты в диалоге (только attach).
- Должно работать без Project Manager UI (MVP в VS Code webview).
- Изменения — микрозадачами (≤3 файла), с обязательными гейтами качества.

## 8) Открытые вопросы (после MVP)

- Структурированный questionnaire definition (не только markdown) для более умного UI.
- Несколько типов анкет (app/cluster/module/feature/bugfix) и выбор типа.
- Поддержка Project Manager (launcher) UI для анкеты.
- Явная валидация анкеты в Core до запуска агента.
