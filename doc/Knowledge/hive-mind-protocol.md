
# Hive Mind Protocol: Архитектура Коллективного Разума для AI-Агентов

Этот документ описывает концепцию **Shared State Architecture** (Архитектура с Разделяемым Состоянием), позволяющую синхронизировать работу нескольких независимых AI-агентов в реальном времени, обходя ограничения изоляции Git Worktree и IDE.

## Проблема
При параллельной работе нескольких агентов (через `git worktree`):
1.  **Изоляция знаний**: Агент 1 не знает, что делает Агент 2, пока не произойдет слияние веток.
2.  **Конфликты контрактов**: Frontend может писать код под старый API, пока Backend уже изменил его в соседней ветке.
3.  **Отсутствие координации**: Нет единого центра управления задачами.

## Решение: Shared State File (Файл Общего Состояния)
Использование единого файла (например, `HIVE_STATE.md`), расположенного по **абсолютному пути** вне зависимости от текущей ветки Git. Все агенты обязаны читать и писать в этот файл.

### Принципы работы

1.  **Единый Источник Правды**: Файл `HIVE_STATE.md` является "доской объявлений" для всех активных агентов.
2.  **Абсолютная Адресация**: Агенты обращаются к файлу по полному системному пути (например, `/Users/user/Projects/Project/.agent/HIVE_STATE.md`), игнорируя контекст своего worktree.
3.  **Атомарность (условная)**: Агенты должны стремиться к коротким записям, чтобы минимизировать риск перезаписи (хотя в текстовом файле race condition возможен, для LLM это приемлемый риск при низкой частоте обновлений).

### Структура `HIVE_STATE.md` (Пример)

```markdown
# HIVE STATE BOARD
Last Updated: 2025-11-22 10:00:00

## Active Agents
### Agent-Frontend (Worktree: feature/login)
- **Status**: IMPLEMENTING
- **Current Task**: Creating Login Form UI
- **Blockers**: Waiting for `POST /api/login` contract update.

### Agent-Backend (Worktree: feature/auth-api)
- **Status**: VERIFYING
- **Current Task**: Updating User Schema
- **Output**: Added `tenant_id` to User model. API now requires `tenant_id` in header.

## Shared Contracts (Real-time Registry)
Здесь агенты публикуют изменения в контрактах ДО коммита.
- [API] `POST /api/login`: Added required field `tenant_id` (String).
- [DB] Table `users`: Added column `is_premium` (Boolean).

## Global Alerts
- 🛑 STOP WORK on `payment` module (User request).
```

### Протокол взаимодействия (Инструкция для Агента)

В системный промпт (или `workflow-master.md`) добавляется правило:

> **HIVE MIND PROTOCOL**:
> 1.  **READ FIRST**: Перед началом любого сложного действия (особенно изменения API или зависимостей) прочитай `HIVE_STATE.md`.
> 2.  **CHECK CONFLICTS**: Если другой агент меняет тот же модуль — остановись и спроси пользователя или дождись завершения.
> 3.  **PUBLISH UPDATE**: Если ты меняешь публичный контракт (API, Schema, Interface) — запиши это в раздел `Shared Contracts` НЕМЕДЛЕННО.
> 4.  **STATUS REPORT**: Обновляй свой статус в разделе `Active Agents` каждые 5-10 шагов.

## Преимущества
- **Телепатия**: Агенты "видят" изменения коллег до того, как они попали в Git.
- **Снижение конфликтов**: Frontend узнает об изменении API мгновенно.
- **Прозрачность**: Пользователь может открыть `HIVE_STATE.md` и видеть пульс всего проекта.

## Реализация
Для внедрения требуется:
1.  Создать файл `HIVE_STATE.md`.
2.  Добавить путь к нему в `.agent/rules`.
3.  Обучить агентов (через промпт) пользоваться им.
