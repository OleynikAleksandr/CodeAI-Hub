## Что произошло
- Выяснили, что при повторном старте VS Code поверх работающего лаунчера расширение не просто подключается к ядру, а переинициализирует провайдеры, из‑за чего активные сессии лаунчера исчезают. Core лог показывает несколько запусков подряд без явного рестарта, значит UI переустанавливает модули даже при совпадающей версии.
- Актуализировал `doc/TODO/todo-critical.md`: добавлен отдельный пункт о том, что при обнаружении уже запущенного **нашего** ядра нужной версии ни расширение, ни лаунчер не должны ничего переустанавливать — только подключаться и синхронизировать UI.

## План на следующую сессию
1. Реализовать правило из `doc/TODO/todo-critical.md`: разделить «ensure» и «attach», чтобы VS Code/лаунчер не трогали провайдеры и ядро, если версия совпадает.
2. После фикса повторить сценарий «лаунчер → VS Code» и задокументировать, что сессии сохраняются.
3. Продолжить задачи по владению портом/lock, затем переходить к блокам Isolation и Unified Session.
