## Проблемы
- **Залипающее ядро предыдущей версии.** После обновления VSIX core 1.1.160 может продолжать слушать порт 8080, даже если UI закрыт. Новый менеджер лишь ждёт, но не закрывает процесс, из-за чего пользователь получает ошибку при старте и должен вручную убивать PID.
- **Нет автоматического выбора свободного порта.** Если 8080 занят (другим приложением или старым core), расширение не переключается на другой порт — запускается бесконечное ожидание и появляется warning.
- **CLI crash = падение оркестратора.** Ошибка Claude CLI (exit code 1 / ProcessTransport) приводит к `Core orchestrator exited with code 1`, поэтому оба клиента теряют сессии и UI зависает на «сканировании модулей».
- **Launcher/extension одновременно запускают core и не умеют восстанавливаться:** при кратном открытии Session оба клиента сталкиваются с race и core не перезапускается корректно.

2. **Изоляция провайдеров**

   - Логировать degraded провайдеры в `/api/v1/status`, чтобы UI мог отображать «Claude unavailable (CLI exited)».
