# Draft v1 — Description Step Help Template (User-Facing)

## Когда показывать этот Help
- Pre-submit: слева вместо Sessions, пока пользователь редактирует `questionnaire.md`.
- Post-submit: по переключателю `Artifacts/Help` в правой панели.

## 1. Что делаем на шаге Description
На этом шаге фиксируем основу продукта:
- какую проблему решаем;
- для кого делаем;
- как пользователь будет использовать продукт в 2–4 ключевых сценариях.

Результат шага — файл:
`Final_Description.md`.

## 2. Что важно заполнить в анкете
Перед `Submit questionnaire` желательно, чтобы в анкете были:
1. Проблема и цель продукта.
2. Целевая аудитория.
3. Ключевые сценарии использования (кратко, человеческим языком).
4. Ограничения/допущения.
5. Явный out of scope (что сейчас не делаем).

## 3. Что произойдёт после Submit
После нажатия `Submit questionnaire`:
1. Запустится Description Agent.
2. Вы продолжите работу в диалоге этой же стадии.
3. Агент будет итеративно обновлять `Final_Description.md`.
4. Вы сможете в любой момент уточнять требования и править направление.

## 4. Как лучше работать с агентом
- Отвечайте конкретно на вопросы с наибольшим влиянием на продукт.
- Если не уверены — это нормально, зафиксируйте как допущение.
- Проверяйте, что в документе не появилось выдуманных деталей.
- Утверждайте финал только когда сценарии и границы продукта вас устраивают.

## 5. Что НЕ нужно делать на этом шаге
- Не нужно описывать всю техническую архитектуру.
- Не нужно детализировать реализацию классов/инфраструктуры.
- Не нужно пытаться закрыть все риски сразу.

## 6. Чеклист готовности к переходу дальше
Можно двигаться к Virtual Simulation, если:
- `Final_Description.md` существует;
- понятны проблема, пользователи и 2–4 сценария;
- зафиксированы ограничения и out of scope;
- отмечены открытые вопросы для следующих шагов.
