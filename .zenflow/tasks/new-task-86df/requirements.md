# Требования: автообновление CLI/SDK и глобальный Gemini CLI Core

## Контекст и текущее состояние
- Обновления CLI/SDK для Claude и Codex выполняются вручную через Settings UI (`ProviderVersionService` → `npm install -g ...@latest`).
- Для Gemini версии читаются из vendor-папки провайдерного модуля (`~/.codeai-hub/providers/gemini/<version>/dist/vendor/node_modules/@google/...`), а `GeminiInstaller.updateToLatest()` обновляет CLI/Core внутри vendor и устанавливает CLI глобально.
- Нужно, чтобы при каждом старте ядра расширения происходила синхронная проверка и обновление глобально установленных CLI/SDK, включая Gemini CLI Core, без привязки к версии в манифесте.

## Цели
1. Автоматически проверять и обновлять глобальные CLI/SDK пакеты для Claude, Codex и Gemini при каждом запуске ядра расширения.
2. Убрать привязку Gemini CLI Core к версии в расширении и перейти на глобальную установку в стандартный npm prefix (`~/.npm-global/lib/node_modules/@google`).
3. Сохранить единый подход к обновлениям: Gemini должен обновляться так же, как Claude и Codex (global + npm latest).
4. Добавить управляемую настройку автообновления в Settings UI для каждого провайдера.
5. Показывать прогресс автообновления в UI во время старта ядра.

## Не цели
- Переработка UX Settings UI за пределами отображения версий и переключателя автообновления.
- Изменение протокола работы SDK/CLI или логики сессий.
- Перенос логов, конфигов или пользовательских данных провайдеров.

## Пользовательские сценарии
- Пользователь запускает расширение и видит, что CLI/SDK обновляются до последних версий, пока ядро ещё не стартовало.
- Пользователь отключает автообновление для конкретного провайдера и использует ручное обновление в Settings.
- Пользователь видит актуальные версии Gemini CLI/Core, прочитанные из глобальной установки, а не из vendor-папки.

## Функциональные требования
1. **Синхронная проверка при старте ядра**: при каждом новом запуске ядра выполняется проверка `latest` для:
   - Claude: `@anthropic-ai/claude-code` и `@anthropic-ai/claude-agent-sdk`.
   - Codex: `@openai/codex` и `@openai/codex-sdk`.
   - Gemini: `@google/gemini-cli` и `@google/gemini-cli-core`.
2. **Синхронное обновление**: если установленная версия не равна `latest`, выполняется `npm install -g <package>@latest` до старта ядра.
3. **Настройка автообновления**:
   - В Settings UI у каждого провайдера есть переключатель автообновления.
   - Если автообновление выключено, старт ядра не инициирует установку и используется только ручной апдейт.
4. **Gemini CLI Core без vendor**:
   - Расширение не использует `~/.codeai-hub/providers/gemini/<version>/dist/vendor/node_modules/@google` как источник версии.
   - Загрузка и использование `@google/gemini-cli-core` происходит только из глобальной установки (npm prefix пользователя).
5. **Settings UI**: версии Gemini CLI/Core читаются из глобальной установки, а не из vendor.
6. **UI прогресс**: запуск ядра отображает прогресс проверки/обновления (status/toast/overlay), пока процесс не завершится.
7. **Устойчивость**: при ошибке обновления ядро продолжает запуск, используя доступные версии; ошибки логируются и отображаются в диагностике.
8. **Минимизация лишних обновлений**: если версия уже соответствует `latest`, повторная установка не выполняется.

## Нефункциональные требования
- Обновления должны быть идемпотентны и блокировать запуск ядра до завершения.
- Действия логируются в существующие каналы (output channel / reporter).
- Решение работает на macOS/Windows/Linux с учётом npm global prefix.

## Ограничения и зависимости
- Для проверки `latest` используется npm registry; при отсутствии сети обновления пропускаются с предупреждением.
- Используется текущий механизм глобальных npm установок (учёт `NPM_CONFIG_PREFIX`).

## Риски
- Несовместимость последних версий CLI/SDK с текущим кодом провайдера.
- Замедление старта ядра при частых обновлениях.
