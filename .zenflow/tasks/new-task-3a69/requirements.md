# PRD: Codex Default Model в Settings

## Контекст
В UI настроек есть вкладка **Codex** (см. `src/client/ui/src/components/settings-view.tsx`), где сейчас отображается только карточка версий провайдера. Требуется добавить новый раздел **Codex Default model**, позволяющий выбрать модель Codex по умолчанию для новых сессий. Список моделей и уровни reasoning берём из официальных документов:
- `doc/Knowledge/Codex_Model_Selection.md`
- `doc/Knowledge/codex-models-official.json`

## Цели
- Дать пользователю возможность выбрать модель Codex по умолчанию для новых сессий.
- Хранить выбор в настройках и применять при открытии новой сессии Codex.
- Для каждой модели настраивать уровень reasoning в отдельном окне.

## Не цели
- Управление моделями Claude/Gemini.
- Автоматическое обновление списка моделей через сеть (используем статический реестр из документации).
- Миграция существующих пользовательских настроек из внешних конфигов Codex CLI.

## Пользовательские сценарии
1. Пользователь открывает Settings → Codex и выбирает модель по умолчанию.
2. Пользователь открывает настройки reasoning для выбранной модели, выбирает уровень, сохраняет.
3. При создании новой сессии Codex система использует выбранную модель и соответствующий ей reasoning.

## Функциональные требования
1. Вкладка **Codex** содержит раздел **Codex Default model**.
2. Пользователь может выбрать модель из списка рекомендованных моделей:
   - `gpt-5.2-codex`
   - `gpt-5.1-codex-max`
   - `gpt-5.1-codex-mini`
   - `gpt-5.2`
3. Для каждой модели доступна настройка **Reasoning effort** (`low`, `medium`, `high`, `xhigh`).
4. Настройка reasoning открывается в **отдельном окне** (модальное/диалоговое окно) для конкретной модели.
5. Выбранная модель и её reasoning сохраняются в настройках и подхватываются при создании новой сессии Codex.
6. Если в настройках сохранена модель, отсутствующая в текущем реестре, система должна:
   - показать предупреждение в UI,
   - подставить безопасный дефолт.

## UX требования
- Раздел **Codex Default model** визуально оформлен в стиле текущих Settings cards.
- Для выбора модели используется понятный контрол (select/list/radio).
- Для reasoning рядом с моделью отображается текущий уровень и кнопка/ссылка **Configure reasoning**.
- Отдельное окно настройки reasoning содержит:
  - название модели,
  - список уровней reasoning,
  - краткое описание каждого уровня (из документации),
  - действия **Save**/**Cancel**.

## Данные и хранение
- Новые поля для Codex-настроек:
  - `defaultModel` (string)
  - `reasoningByModel` (map: modelId → reasoningLevel)
- Значения по умолчанию:
  - `defaultModel`: `gpt-5.2-codex`
  - `reasoningByModel[modelId]`: `medium`

## Ограничения и зависимости
- Источник моделей — статическая документация (`codex-models-official.json`).
- Уровни reasoning ограничены списком: `low`, `medium`, `high`, `xhigh`.
- В продакшене настройки должны быть совместимы с существующей схемой `settings.json`.

## Вопросы и допущения
1. Нужно ли показывать **legacy модели** из документации в UI (отдельная группа)?
2. Разрешить ли ручной ввод кастомной модели, если пользователь использует нестандартный backend?
3. Как именно выглядит «отдельное окно» для reasoning: модальное окно внутри WebView или переход на отдельный экран Settings?
4. Нужно ли отображать текущий effective model/reasoning, если значение приходит из env `CODEX_DEFAULT_MODEL`?

## Критерии приемки
- Вкладка Codex содержит раздел **Codex Default model**.
- Выбор модели и reasoning сохраняется и восстанавливается при повторном открытии Settings.
- Новая сессия Codex использует выбранную модель и соответствующий reasoning.
- Reasoning настраивается в отдельном окне и сохраняется для каждой модели отдельно.
